== 8. INSTANCE MEMORY (SGA / PGA sizing verdicts) ==
One row per instance and memory area, judged on the last 30 days of AWR up to the
database's newest snapshot (WINDOW; DAYS = days sampled in it). An uptime shorter than
24 hours adds no advisor evidence (a cold cache distorts the estimates); its symptoms count.
UNDERSIZED: the advisor estimates a material gain at a larger size AND a pressure symptom
was observed. Either one alone grades OK, and the reason names it. The PGA limit has no
advisor: it is UNDERSIZED when a window peak reached 90% of pga_aggregate_limit.
OVERSIZED: the advisor estimates almost no cost at a smaller size, no pressure was observed,
and at least 21 days were sampled. OK: no change advised. INSUFFICIENT_EVIDENCE: the
reason says what is missing (advisor history, AMM, memory history, 7 sampled days).
SGA balance: THRASHING = ASMM keeps moving memory between the buffer cache and the shared
pool, DRIFTING = it squeezed one pool in favour of the other. MODE: ASMM, AMM or MANUAL.
SUGGESTED: a size the advisor evaluated (PGA limit: the size that puts the peak at 90%),
at most 2 times and at least 1/2 of the current size. It is one step: re-evaluate
after the change. Empty: no change advised. Under ASMM a buffer cache or shared pool
suggestion is a floor (the least ASMM may give the pool), not a fixed size, and so is the
floor of a THRASHING balance.
HOST = Y: the suggestion plus the rest of the instance passes 80% of the host's physical
memory (empty: unknown, or nothing suggested). Other instances on the same host are not seen.
SGA = Y: the buffer cache or shared pool floor is more than the two pools hold together now,
so it cannot fit in sga_target: raise sga_target first.
Advice only: the suite never changes a parameter, and memory verdicts raise no alert.
