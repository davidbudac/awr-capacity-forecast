Getting started

Install and first report

Two ways to deploy one install. The suite always copies AWR over a database link and runs on the copies. Measure one database by making it its own target: the suite lives in a PDB owner and reads its CDB's AWR over a loopback link. Or measure a fleet: each measured database gets only a read-only user, and one repository database copies their AWR and runs the suite for all of them. Nothing is written to AWR either way.

Path A

Measure one database

quickstart.sh creates the reader and the suite owner, runs the preflight, installs, copies this database's AWR over a loopback link and spools the first capacity report, in one run on the measured database.

On the measured database: a reader in the root, the suite in a PDB owner History: kept by the suite, 400 days by default; the first copy holds what AWR still has Time: a few minutes
Path B

Measure a fleet

Prepare each target with a read-only user, install the suite on a repository database, register the targets there and copy their AWR on a schedule.

On each measured database: one read-only user, nothing else History: kept by the repository, 400 days by default Time: a few minutes per target
i

Requirements: Oracle Database 19c or newer with the Diagnostics Pack (AWR) on every measured database, sqlplus, a sysdba connection, and a pga_aggregate_limit with about 1.5 GB to spare per session that runs a report, on whichever database runs the suite (Memory (PGA)). Other options: Advanced install.

▸

Nothing installed yet? @standalone/tbspc_capacity.sql is the Tier 1 tablespace forecast as one read-only SELECT over DBA_HIST_*, run on the database itself (CDB$ROOT shows every container). One row per container and permanent tablespace: used, limit, MB per day, R², size at +30 and +90 days, days to full, space to add, quality and CRIT / WARN / OK. It creates nothing and keeps no history, and it has no overrides, anomalies or ML.

Path A

Measure one database

The suite runs in a PDB of the measured database and copies the CDB's AWR over a loopback database link, the way a repository reads any target.

1

Clone the repository where sqlplus runs

On the database host, / as sysdba needs no password.

DB host · bashyou run
git clone https://github.com/davidbudac/awr-capacity-forecast.git
cd awr-capacity-forecast
2

Run the quickstart

Creates the read-only reader C##AWRRDR (with a random password that never leaves the session) and the schema-only owner AWRCAP in the one open PDB, runs the read-only preflight, installs, registers this database as its own target, copies its AWR and spools the first report. Needs SYSDBA. Re-runnable: a re-run reuses the reader, the owner and the target. On a preflight FAIL it stops before installing; fix and re-run, or DEFINE force_install = Y in SQL*Plus to install anyway. With more than one open PDB, name one: CAP_CONTAINER=PDB1 ./quickstart.sh.

DB host · bashyou run
./quickstart.sh                    # connects as / as sysdba

From SQL*Plus, started in the repository directory:

SQL*Plus · CDB$ROOTalternative
sqlplus / as sysdba
SQL> @quickstart.sql

Expected tail of the output:

outputexpect

============================================================

...

3

Read the report

Plain text, eight sections: days-to-full per tablespace, growth forecasts, anomalies, CPU trend, then the fixed-ceiling series. The first lines summarise what is heading for a limit.

DB host · bashyou run
less reports/cap_report_*.txt

Samples: HTML report, text report (both drivers run against a fictional e-commerce database with 150 days of designed history). Later reports: @report/report.sql from the repository directory, in the owner's schema (ALTER SESSION SET CONTAINER = PDB1, then ALTER SESSION SET CURRENT_SCHEMA = AWRCAP), or report/run_report.sh "/ as sysdba" --container PDB1 --schema AWRCAP. Usage covers each section.

!

INSUFFICIENT_HISTORY on a fresh database. Stock AWR keeps 8 days, so the first copy holds 8 days, and a forecast needs at least 14 daily points. The copies grow with every collect: schedule the hourly one, and the forecasts fill in over the following weeks. Raising AWR retention (optional) gives the next collect more at once.

SQL*Plus · the suite owneronce
SQL> ALTER SESSION SET CONTAINER = PDB1;
SQL> ALTER SESSION SET CURRENT_SCHEMA = AWRCAP;
SQL> @install_jobs.sql                               -- jobs created disabled
SQL> EXEC DBMS_SCHEDULER.ENABLE('AWRCAP.CAP_COLLECT_JOB')   -- hourly at :05
SQL*Plus · CDB$ROOToptional · once
SQL> EXEC DBMS_WORKLOAD_REPOSITORY.MODIFY_SNAPSHOT_SETTINGS(retention => 90*24*60);  -- 90 days
quickstart.sql, step by step
StepScriptDoes
1target/self.sqlIn CDB$ROOT: picks the PDB, gives the reader a random password, runs target/prepare.sql (the reader's grants and CONTAINER_DATA) and target/check.sql (Diagnostics Pack, AWR retention, the grants), then switches to the PDB.
2create_owner.sqlThe schema-only owner AWRCAP, with CREATE DATABASE LINK and no AWR grant.
3doctor.sqlRead-only preflight of the owner: schema, privileges, the features the history supports. Prints a PASS / WARN / FAIL checklist.
4install.sqlCreates the views, tables and packages in the owner, deploy_mode = repository. Idempotent; re-running keeps changed knob values. Exits with an error if any object is invalid. Skipped when step 3 reported a FAIL.
5repository/self.sqlRegisters this database as target CDB1 over //localhost:<listener port>/<the root's default service> (or rebuilds the link of one an earlier run registered) and copies its AWR.
6report/report.sqlThe read-only text report, spooled to reports/.

A permanent install. install.sh runs the same steps and also trains the Tier 2 models and creates the scheduler jobs, disabled (CAP_COLLECT_JOB hourly, CAP_NIGHTLY_JOB at 01:00). --set JOBS_ENABLE=Y turns both on:

DB host · bashyou run
./install.sh --profile standalone          # silent; ./install.sh alone asks every question
Path B

Measure a fleet

One repository database measures every registered target. It copies each target's AWR over a database link and runs the whole suite on the copies.

What each side gets
DatabaseGetsWrites
Target, each measured databaseA read-only common user C##AWRRDR: CREATE SESSION, direct SELECT on the twenty-eight DBA_HIST_* views the suite reads, and CONTAINER_DATA = ALL so it sees every PDB. No suite objects.Nothing. Every statement the repository runs there is a SELECT.
Repository, any 19c database or PDB that can reach each target's listenerThe whole suite in deploy_mode = repository, the target registry, one copy table per AWR view, the hourly collect job and the nightly job, which also purges old copies. It reads no AWR of its own.Its own CAP_* tables only.
1

Prepare each target

On each measured database, from a clone of this repository, as SYSDBA in CDB$ROOT (or in a non-CDB). The profile runs target/prepare.sql, which creates the reader, then target/check.sql, which checks its grants, the Diagnostics Pack and AWR retention. Nothing else on the target changes.

target host · bashyou run
export CAP_READER_PW='<reader password>'
./install.sh --profile target

From SQL*Plus, started in the repository directory:

SQL*Plus · CDB$ROOTalternative
sqlplus / as sysdba
SQL> DEFINE reader_pw = <reader password>
SQL> @target/prepare.sql
SQL> @target/check.sql

The prepare step ends with the line to run on the repository:

outputexpect
  Reader C##AWRRDR is ready. Register this target on the repository
  (as the suite owner there). Check the address against lsnrctl status:
    EXEC cap_repo.add_target('CDB1', '//db-prod-01.example.com:1521/cdb1', 'C##AWRRDR', '<password>', p_global_name => 'CDB1.EXAMPLE.COM')
    EXEC cap_repo.collect
  The global name CDB1.EXAMPLE.COM names the link only where the repository runs with GLOBAL_NAMES = TRUE.
2

Install the repository

On the repository database, as SYSDBA. The profile creates the owner C##AWRCAP with CREATE DATABASE LINK and no AWR grant, runs the preflight, installs deploy_mode = repository and creates the two scheduler jobs, disabled. Add --set CONTAINER=<PDB> to install into a PDB, where the owner is AWRCAP.

repository host · bashyou run
./install.sh --profile repository
3

Register each target and copy its AWR

Run the line step 1 printed, in the owner's schema. add_target creates the database link, probes every copied view through it and finds the target's DBIDs; a wrong password or a missing grant fails the call and leaves nothing behind. The first collect copies all the AWR the target still holds.

SQL*Plus · repositoryyou run
sqlplus / as sysdba
SQL> ALTER SESSION SET CURRENT_SCHEMA = C##AWRCAP;
SQL> SET SERVEROUTPUT ON
SQL> EXEC cap_repo.add_target('CDB1', '//db-prod-01.example.com:1521/cdb1', 'C##AWRRDR', '<reader password>', p_global_name => 'CDB1.EXAMPLE.COM')
SQL> EXEC cap_repo.collect('CDB1')
outputexpect
  DBID 1214129087 registered for CDB1
  target CDB1 registered over link CAP_CDB1; containers visible: CDB$ROOT, PDB$SEED, PDB1
  next: EXEC cap_repo.collect('CDB1')
...
  CDB1 DBID 1214129087: snap_id 2700..3865, 154212 rows (2 s)
4

Turn on the jobs

CAP_COLLECT_JOB copies new snapshots from every enabled target hourly. CAP_NIGHTLY_JOB runs once a night. It first deletes copies older than repo_retention_days, then retrains, refreshes and writes the alert file as on a single database (Scheduler jobs).

SQL*Plus · repositoryyou run
SQL> EXEC DBMS_SCHEDULER.ENABLE('C##AWRCAP.CAP_COLLECT_JOB')
SQL> EXEC DBMS_SCHEDULER.ENABLE('C##AWRCAP.CAP_NIGHTLY_JOB')
5

Run the report

One report covers every target, and its header names them. --target limits it to one; the file is then named after that target instead of fleet.

repository host · bashyou run
report/run_report.sh "/ as sysdba" --schema C##AWRCAP --html                # every target
report/run_report.sh "/ as sysdba" --schema C##AWRCAP --html --target CDB1  # one target
▸

History builds up in the repository. A target keeps its default AWR retention. The first collect copies what it still has, and from then on the repository keeps every snapshot for repo_retention_days (400 by default), so the forecasts fill in after about two weeks of collecting. Pausing a target, rotating the reader's password, removing a target and checking collect health: Repository mode.

▸

Read-only against AWR. The suite writes only to its own CAP_* tables (see Impact on the database). Remove everything again with @uninstall.sql, which also drops the repository's database links.
