Getting started

Install and first report

Two ways to deploy. Measure one database by installing the suite on it, where it reads its own AWR. Or measure a fleet: each measured database gets only a read-only user, and one repository database copies their AWR and runs the suite for all of them. Nothing is written to AWR either way.

Path A

Measure one database

quickstart.sh runs the preflight, installs the views and spools the first capacity report, in one run on the measured database.

On the measured database: the whole suite, in one schema History: what its AWR keeps (8 days on a stock database) Time: about a minute
Path B

Measure a fleet

Prepare each target with a read-only user, install the suite on a repository database, register the targets there and copy their AWR on a schedule.

On each measured database: one read-only user, nothing else History: kept by the repository, 400 days by default Time: a few minutes per target
i

Requirements: Oracle Database 19c or newer with the Diagnostics Pack (AWR) on every measured database, sqlplus, a sysdba connection, and a pga_aggregate_limit with about 1.5 GB to spare per session that runs a report, on whichever database runs the suite (Memory (PGA)). Other options: Advanced install.

Path A

Measure one database

The suite runs on the measured database and reads its AWR in CDB$ROOT.

1

Clone the repository where sqlplus runs

On the database host, / as sysdba needs no password.

DB host · bashyou run
git clone https://github.com/davidbudac/awr-capacity-forecast.git
cd awr-capacity-forecast
2

Run the quickstart

Runs the read-only preflight, installs every object into the current schema and spools the first report. Re-runnable. On a preflight FAIL it stops before installing; fix and re-run, or DEFINE force_install = Y in SQL*Plus to install anyway.

DB host · bashyou run
./quickstart.sh                    # connects as / as sysdba

From SQL*Plus, started in the repository directory:

SQL*Plus · CDB$ROOTalternative
sqlplus / as sysdba
SQL> @quickstart.sql

Expected tail of the output:

outputexpect
  All CAP* objects valid in schema SYS.
============================================================
 Install complete (deploy_mode = local, schema = SYS).
============================================================
...
Report written to: reports/cap_report_CDB1_202609221410.txt
3

Read the report

Plain text, eight sections: days-to-full per tablespace, growth forecasts, anomalies, CPU trend, then the fixed-ceiling series. The first lines summarise what is heading for a limit.

DB host · bashyou run
less reports/cap_report_*.txt

Samples: HTML report, text report (both drivers run against a fictional e-commerce database with 150 days of designed history). Later reports: @report/report.sql from the repository directory. Usage covers each section.

!

INSUFFICIENT_HISTORY on a fresh database. Stock AWR keeps 8 days; a forecast needs at least 14 daily points. Raising retention (optional, the only change to Oracle on this page) fills the forecasts in over the following weeks.

SQL*Plus · CDB$ROOToptional · once
SQL> EXEC DBMS_WORKLOAD_REPOSITORY.MODIFY_SNAPSHOT_SETTINGS(retention => 90*24*60);  -- 90 days
quickstart.sql, step by step
StepScriptDoes
1doctor.sqlRead-only preflight: target schema, Diagnostics Pack, DBA_HIST_* grants, privileges, AWR retention, history per source and the features it supports. Prints a PASS / WARN / FAIL checklist.
2install.sqlCreates the views, seven small tables and two packages in the current schema, local mode. As / as sysdba that schema is SYS (the installer warns). Idempotent; re-running keeps changed knob values. Exits with an error if any object is invalid. Skipped when step 1 reported a FAIL.
3report/report.sqlThe read-only text report, spooled to reports/.

A permanent install. The quickstart installs into SYS. For the lasting setup, install.sh creates a dedicated owner (C##AWRCAP), runs the preflight, installs, trains the Tier 2 models and creates the scheduler jobs, disabled:

DB host · bashyou run
./install.sh --profile standalone          # silent; ./install.sh alone asks every question
Path B

Measure a fleet

One repository database measures every registered target. It copies each target's AWR over a database link and runs the whole suite on the copies.

What each side gets
DatabaseGetsWrites
Target, each measured databaseA read-only common user C##AWRRDR: CREATE SESSION, direct SELECT on the seventeen DBA_HIST_* views the suite reads, and CONTAINER_DATA = ALL so it sees every PDB. No suite objects.Nothing. Every statement the repository runs there is a SELECT.
Repository, any 19c database or PDB that can reach each target's listenerThe whole suite in deploy_mode = repository, the target registry, one copy table per AWR view, and the collect and purge jobs. It reads no AWR of its own.Its own CAP_* tables only.
1

Prepare each target

On each measured database, from a clone of this repository, as SYSDBA in CDB$ROOT (or in a non-CDB). The profile runs target/prepare.sql, which creates the reader, then target/check.sql, which checks its grants, the Diagnostics Pack and AWR retention. Nothing else on the target changes.

target host · bashyou run
export CAP_READER_PW='<reader password>'
./install.sh --profile target

From SQL*Plus, started in the repository directory:

SQL*Plus · CDB$ROOTalternative
sqlplus / as sysdba
SQL> DEFINE reader_pw = <reader password>
SQL> @target/prepare.sql
SQL> @target/check.sql

The prepare step ends with the line to run on the repository:

outputexpect
  Reader C##AWRRDR is ready. Register this target on the repository
  (as the suite owner there). Check the address against lsnrctl status:
    EXEC cap_repo.add_target('CDB1', '//db-prod-01.example.com:1521/cdb1', 'C##AWRRDR', '<password>')
    EXEC cap_repo.collect
2

Install the repository

On the repository database, as SYSDBA. The profile creates the owner C##AWRCAP with CREATE DATABASE LINK instead of AWR grants, runs the preflight, installs deploy_mode = repository and creates the five scheduler jobs, disabled. Add --set CONTAINER=<PDB> to install into a PDB, where the owner is AWRCAP.

repository host · bashyou run
./install.sh --profile repository
3

Register each target and copy its AWR

Run the line step 1 printed, in the owner's schema. add_target creates the database link, probes every copied view through it and finds the target's DBIDs; a wrong password or a missing grant fails the call and leaves nothing behind. The first collect copies all the AWR the target still holds.

SQL*Plus · repositoryyou run
sqlplus / as sysdba
SQL> ALTER SESSION SET CURRENT_SCHEMA = C##AWRCAP;
SQL> SET SERVEROUTPUT ON
SQL> EXEC cap_repo.add_target('CDB1', '//db-prod-01.example.com:1521/cdb1', 'C##AWRRDR', '<reader password>')
SQL> EXEC cap_repo.collect('CDB1')
outputexpect
  DBID 1214129087 registered for CDB1
  target CDB1 registered over link CAP_CDB1; containers visible: CDB$ROOT, PDB$SEED, PDB1
  next: EXEC cap_repo.collect('CDB1')
...
  CDB1 DBID 1214129087: snap_id 2700..3865, 154212 rows (2 s)
4

Turn on the jobs

CAP_COLLECT_JOB copies new snapshots from every enabled target hourly. CAP_PURGE_JOB deletes copies older than repo_retention_days daily. The refresh and retrain jobs work as on a single database (Scheduler jobs).

SQL*Plus · repositoryyou run
SQL> EXEC DBMS_SCHEDULER.ENABLE('C##AWRCAP.CAP_COLLECT_JOB')
SQL> EXEC DBMS_SCHEDULER.ENABLE('C##AWRCAP.CAP_PURGE_JOB')
SQL> EXEC DBMS_SCHEDULER.ENABLE('C##AWRCAP.CAP_REFRESH_JOB')
5

Run the report

One report covers every target, and its header names them. --target limits it to one; the file is then named after that target instead of fleet.

repository host · bashyou run
report/run_report.sh "/ as sysdba" --schema C##AWRCAP --html                # every target
report/run_report.sh "/ as sysdba" --schema C##AWRCAP --html --target CDB1  # one target
▸

History builds up in the repository. A target keeps its default AWR retention. The first collect copies what it still has, and from then on the repository keeps every snapshot for repo_retention_days (400 by default), so the forecasts fill in after about two weeks of collecting. Pausing a target, rotating the reader's password, removing a target and checking collect health: Repository mode.

▸

Read-only against AWR. The suite writes only to its own CAP_* tables (see Impact on the target database). Remove everything again with @uninstall.sql, which also drops the repository's database links.
