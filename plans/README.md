in one session. Plans 001, 003, 004, 008A need one run each; 006 and 007 two
each. Do not run two harnesses on one schema, and prefer not to run two at
once on the 2-vCPU VM when a plan compares timings (006, 007, 008).

## Findings considered and rejected

So nobody re-audits them:

- **Memory verdicts of a database whose AWR stopped stay "actionable"**
  (proposed: add `is_current` to `CAPR_MEM_VERDICT`). Rejected on reading the
  code: the forecasts behave the same way. `is_current` in the `CAPF_` views
  is relative to the database's *own* newest day (`ddl/30_forecast_views.sql:44-46`),
  so a stopped database's fits stay current too; `DATA_STALE` is the one
  place that compares with `SYSDATE`. Hiding a retired target from reports
  would be a suite-wide design change, not a memory-view fix.
- **START restart in the standalone query waits for 14 days of data**: a
  documented trade-off (`standalone/README.md`, "Only when at least 14 days
  are left").
- **Live ceiling joined by tablespace name; PDB$SEED rows in the suite's
  tablespace usage; advisor "current size" taken from the instance's latest
  snapshot**: each depends on Oracle behaviour nobody verified (rows kept
  after a drop and re-create, seed rows in `DBA_HIST_TBSPC_SPACE_USAGE`, an
  advisor skipping one snapshot). Investigate on a real database before
  planning anything.
- **Splitting `test/run_test.sql`, `ddl/42`, `ddl/45`, `report_brief.sql`**:
  each is one layer in load order; more files cost more than they give under
  SQL*Plus `@@` path rules. Splitting `run_test.sql` is worth it only after
  measuring where its 30 minutes go.
- **`elk/export.sh` argument validation, the ESM model swap window (drop then
  rename), `:latest` lab images, orphan pages under `docs/diagrams/` and
  `docs/mockups/`, hard-coded `dbmint` in the test levers, splitting
  `CLAUDE.md`**: real but low value or the maintainer's call; not planned.

## Audited, found, not selected for a plan this round

The maintainer chose not to plan these yet; they remain open findings.

- **A purge spread over two days counts as two cliffs = CYCLIC**
  (`ddl/30_forecast_views.sql:257-275`, mirrored in the standalone query
  `:301-311`): no reset, and the tablespace's full-date alert is off for up
  to `train_days`.
- **`test/run_test.sql` assumes the fixture was loaded today**
  (`--no-fixture` the next morning fails at `:4621`). The other half of this
  finding is closed (2026-11-12): `test/check.sh` is the one entry point for
  the offline checks, `test/dbmint_harness.sh` and
  `.github/workflows/check.yml` run it, and it includes `test/docs_lint.sh`.
  The lints now read tracked files only, so a file under `reports/` no
  longer fails them.
- **The ORDS module is public and reads live views per request**, and
  `install.sh` `ORDS=Y` publishes it (`grafana/ords/awrcap_module.sql:15`).
- **`cap_results.purge` is never scheduled; the alert spool file is written
  in place; a re-install does not quiesce running jobs.**
- **HTML page robustness**: unguarded `JSON.parse`, hour 24 not drawn, hover
  on an empty card throws (`report/html/report.js:4,633,1176`).

## Findings closed outside a plan
